# lecture-quality-analyzer — STT 강의 품질 EDA 정리

> STT로 전사된 강의 15편을 분석해, 이후 자동 채점 파이프라인(규칙 + LLM)의
> 기준을 데이터로 확정하기 위한 EDA. 모든 수치는 실제 실행 결과 기준이다.

---

## 0. 한눈에 보는 결론

- **분석 단위는 발화(utterance)가 아니라 kss 문장**, **분석 윈도우는 도입부 30분**으로 통일.
- 정성 항목(4·5·9·10·13)은 **규칙(키워드·regex)으로 후보를 넓게 모으고 → LLM이 정밀 판단**하는 2단 구조.
- EDA의 역할은 "어디까지 규칙으로 거르고, 어디부터 LLM에 맡길지"의 **경계선을 데이터로 찾는 것**.

---

## 1. 데이터 개요

- STT 강의 **15편** (`2026-02-02` ~ `2026-02-27`, 동일 강사·동일 과목: 백엔드/DB).
- 원본 포맷: `<HH:MM:SS> speaker_id: 발화 텍스트`.
- 전처리 산출물: `backend/data/processed/utterances_all.csv` (12컬럼).

| 컬럼 | 의미 |
|------|------|
| lecture_id, date | 강의 식별자·날짜 |
| timestamp, speaker_id | 원본 시각·화자 ID |
| text_raw, text_clean | 원문·정제 발화 |
| sec_raw, sec_fixed | 초 변환·오전/오후 보정 |
| elapsed_sec, duration_sec | 경과 초·다음 발화까지 간격 |
| word_count, char_count | 어절 수·글자 수 |

## 2. 전처리 — 무엇을 했고 왜 그렇게 했나

### 2-1. 짧은 발화 필터 — **미적용**

- EDA 결과: word_count 중앙값 13·평균 13.5어절. **1어절 이하 1.8%, 2어절 이하 5.7%**.
- 2어절 이하를 직접 샘플링해 보니 모두 의미 있는 STT 분절 조각이었고, 노이즈(빈 발화·감탄사 단독)는 거의 없었다.
- → **결론**: 짧은 발화 제거는 하지 않는다. 데이터가 깨끗해 필터가 오히려 정보를 버린다.

[그래프 삽입: word_count 히스토그램 + min_words 임계값별 제거 비율 막대]

### 2-2. 인접 발화 병합(merge_utterances) — **폐기**

- gap_sec 임계값별 병합 후보를 보면 3초 이하 gap이 다수.
- 분석: **짧은 발화일수록 다음 발화까지 gap이 자연히 작다(역인과)**. gap 기준 병합은 의미 단위가 아니라 단지 빠르게 이어진 발화를 묶어 의미를 왜곡.
- → **결론**: merge_utterances 폐기. 발화 묶음은 "쉬는 시간 단위 블록 분리 + kss 문장 분리"로 대체.

[그래프 삽입: duration_sec 분포(≤30초) + gap_sec 임계값별 병합 후보 비율 막대]

### 2-3. 발화 간 간격 / 쉬는 시간

- duration_sec 중앙값 10초·평균 18.8초. 10분 초과 55건, 1시간 초과 27건.
- 큰 gap의 정체: 쉬는 시간·점심·실습 대기·설치 대기가 혼재. 단순 gap만으로는 구분 불가.
- (추가 탐색 필요: break 임계값의 **강사 일반화** — 현재는 단일 강사라 검증 불가. 다강사 데이터 확보 후 재튜닝 필요)

## 4. 화자 분석 (speaker_id)

- speaker_id 개수: 1개 9강의 / 2개 3강의 / 3개 3강의.
- 변경 지점의 gap은 대부분 쉬는 시간과 일치. 예외: `2026-02-26` gap 1.8분(서버 끊김 후 재접속).
- 분석: speaker_id 변경 = 화자 교체가 아니라 **쉬는 시간/끊김 후 동일 강사 재접속**. 변경 전후 모두 강사 발화.
- → **결론**: speaker_id 변경 ≠ 화자 변경. 모두 동일 강사로 간주. 강사 ID = 강의별 최다 발화 speaker_id.

## 5. 쉬는 시간 블록 분리 + kss 문장 분리

### 5-1. break(쉬는 시간) 탐지

- 규칙: **10분 이상 gap + 직전 ±2 발화에 쉬는 시간 키워드**, 1시간 이상은 무조건 break.
- 키워드는 bare `'쉬'`가 아니라 활용형(`쉬는/쉬었/쉴/쉬겠/잠깐 쉬…`)으로 제한 → `쉬운/아쉬운/쉬프트` 오탐 위험 제거(탐지 결과는 45개로 동일).
- 탐지 break **45개**(강의당 평균 3.0). false positive(설치 대기 685초, 강의 중간 710초)는 정상 제외.

### 5-2. 블록 생성 + 소형 블록 병합

- 블록: 병합 전 60개 → 소형 블록(<20발화) 11개를 직전 블록에 병합 → **49개**(강의당 평균 3.3).

### 5-3. kss 문장 분리

- regex(종결어미 split)는 구어체 중간 절을 과분리 → **kss `backend='fast'`** 채택.
- 블록당 문장 수 평균 **343개**(101~768).

### 5-4. kss backend 비교 (`fast` vs `mecab`)

| 항목 | `fast` | `mecab` |
|------|--------|---------|
| 처리 시간(전체 도입부 30분) | 0.04초 | 12.84초 (~320배) |
| 총 문장 수 | 2,168 | 2,679 (+24%) |
| 목표 키워드 탐지 합 | 91 | 94 (+3%) |
| 복습 키워드 탐지 합 | 200 | 202 (+1%) |

- mecab이 더 정확하게 분리(명시적 마침표 미스 교정, 목표/복습 문장 분리)하지만, **다운스트림 탐지 지표는 3% 미만 변동**.
- → **결론**: `fast` 유지. 지표가 안 움직이는데 의존성·속도 비용을 전 파이프라인에 얹을 이유가 약함. (LLM 인용 셀만 선택적 mecab 여지)

[그래프 삽입: 블록당 kss 문장 수 분포 (선택)]

## 6. 정성 항목 공통 전략 — 규칙 + LLM 2단

항목 4·5·9·10·13은 모두 **정답 라벨이 없는 정성(high-inference) 항목**이다.

| 단계 | 도구 | 목표 | 우선순위 |
|------|------|------|----------|
| 1차 | 키워드 / regex | 후보 문장을 싸게·넓게 수집 | recall |
| 2차 | LLM (Gemini 2.5 Flash) | 후보의 진위·질 정밀 판단·채점 | precision |

- LLM 호출은 **캐시 + `sleep(32초)`**로 무료 티어(2 RPM / 50 RPD) 제약에 대응. 재실행 시 API 재호출 0.

## 7. 항목별 EDA 결과

### 항목 4 — 학습 목표 안내 (목표 + 순서 2축)

- 채점 기준상 **목표를 말한 뒤 수업 진행 순서까지 안내했는가**가 2~5점을 가른다 → 목표·순서 둘 다 본다.
- 접근: 넓은 키워드 → 키워드 정밀화(실패) → **시작 블록(25문장) + GOAL 키워드 밀집 윈도우**를 연속
  passage로 묶어 → LLM이 **목표 명시(goal_stated) + 순서 안내(order_mentioned)** 2축 판정.
  - 구간 선택 근거: GOAL hit은 보통 도입부 초반에 밀집하나 `02-06`·`02-24`는 목표가 중반에 나오고,
    `02-13`·`02-27`은 본문 키워드가 더 밀집 → "시작 블록 + 밀집 윈도우" 병합으로 둘 다 커버.
- **LLM 2축 결과**:

| 지표 | 결과 |
|------|------|
| 목표 명시 | **15/15 (100%)** |
| 순서 안내 | **9/15 (60%)** |
| 점수 분포 | 3점 6개 / 5점 9개 / 1점 0개 |

- 분석: 이 강사는 거의 모든 강의에서 목표를 안내한다(100%). 변별력은 "목표만(3점) vs 목표+순서(5점)".
  키워드 단독(v1)으로 0건(1점)이던 `02-03`·`02-25`는 **추출 누락**이었을 뿐, 문맥 블록을 주니
  실제 목표·순서가 드러났다(`02-25` = 인덱스 개념+순서 → 5점).
- 채점 매핑: **1점** goal_stated=False(데이터셋엔 없음) / **3점** 목표만 / **5점** 목표+순서 /
  **4점** 순서 불완전 시 LLM 보조.

[그래프 삽입: 강의별 목표 명시 / 순서 안내 2축 막대 (O/X)]

(추가 탐색: 4↔5 세부 차등(순서의 구체성) 기준 정교화, `02-03` 복습 회고형의 목표 판정 경계선 → 제외 기준 강화 여지)

### 항목 5 — 전날 복습 연계

- 도입부 30분·kss 동일 골격.

- 분석: 탐지율 100%는 성과가 아니라 **키워드가 너무 흔해서** 잡힌 결과. hit_count ≠ 품질.
- → 탐지 여부(0건=1점)만 EDA로 거르고, 2~5점(복습의 구체성·연결성)은 LLM에 이관.

### 핵심 내용 강조 — 키워드 추출 (TF-IDF → TextTiling)

- 평가 항목 "중요한 내용을 반복·강조하여 전달하는가"의 기준이 될 **핵심 내용(키워드)** 을 추출.
  Liu et al. 2009(N09-1070) §4.1의 **TF-IDF + POS filtering(명사)** 방식.
- **전제 검증 — 쉬는 시간 ≠ 토픽 경계**: 쉬는시간 경계 너머 인접 블록 유사도(0.537)가 블록 내부
  (0.528)와 거의 동일 → 분할 신호 ≈ 0. 토픽이 연속으로 흐름.

| 단계 | 단위 | 강의당 | 결과 |
|------|------|--------|------|
| 블록 TF-IDF | 쉬는시간 블록 | 평균 3.3개 | 거친 주제 (제약/트랜잭션/DML) |
| **TextTiling** | 토픽 세그먼트 | 평균 7.1개 (3~10) | 세밀·일관 (참조관계·세이브포인트·임시변수) |

- 어휘 응집도 골을 찾는 TextTiling이 쉬는시간 블록보다 **세밀하고 토픽이 또렷한 세그먼트**를 만든다
  (예 02-13: 프로시저/트리거 → 참조관계 → 트랜잭션 → 세이브포인트 → 임시변수).
- **형태소 분석기 Mecab → Kiwi 교체** (비교 실험 후): Mecab은 STT 외래어를 쪼개(`인스턴스→인/스턴스`,
  `컨스트레인트→컨스/트레인/트`) hack(어절-stem·`의`처리·동사strip)으로 우회해야 했으나, Kiwi는 분석
  단계에서 근본 해결(`인스턴스`·`컨스트레인트` 단일 토큰, `의`=조사 정확)해 hack 제거. 전체 코퍼스 15초.
- **영문(SL) 토큰 복구**: `SQL·DDL·DML·DCL·TCL·DB·PK·EMP·API·IO·MySQL·NIO` 등 **32개 핵심 용어를 키워드로
  복구**(이전엔 영문 시작 토큰을 통째로 버려 누락).
- **음차 정규화 사전 + 변형 통합**: `아이오/입출력→IO`·`마이에스큐*→MySQL` 토큰 매핑 + 잔여 파편
  (`셀렉→셀렉트`) 통합. 사전어 보호로 `기본키·문자열·마이너스·인덱싱` 오병합 0건.
- → **결론**: "핵심 내용"의 기준 단위는 **TextTiling 세그먼트**. 세그먼트 키워드를 이후 "반복·강조"
  채점의 근거로 사용. 산출물: `keywords_by_block.csv`, `keywords_by_segment.csv`.

## 8. 종합 — 규칙과 LLM의 분업 경계

| 항목 | 규칙(EDA)이 거른 것 | LLM에 맡긴 것 | 그렇게 나눈 근거 |
|------|--------------------|---------------|------------------|
| 4 목표 안내 | 0건 = 1점 / regex 후보 | 목표 진위·구체성(2~5점) | 정형 문구 미사용 → 키워드 정밀화 실패 |
| 5 복습 연계 | 0건 = 1점 / 복습 문장 탐지 | 복습의 구체성·연결성 | 탐지율 100%지만 건수 ≠ 품질 |
| 9 개념 정의 | 정의 문장 절대 수 | 단순 명명 vs 진짜 정의 | 분모 부재로 rate 불가 / 패턴 오탐 |
| 10 비유·예시 | 예시 후보 + 타이밍 커버리지 | (후보를 13으로 전달) | `처럼` 오탐 다수 |
| 13 예시 적절성 | (항목 10 후보 재사용) | 수준·관련성 판단 | 적절성은 의미 판단 영역 |

**일관된 원칙**

1. 단위는 kss 문장, 윈도우는 도입부 30분 — 모든 항목이 동일 전제 위에서 비교 가능.
2. 규칙은 recall, LLM은 precision — 규칙이 싸게 넓게 모으고, 비싼 LLM은 좁혀진 후보에만.
3. 모든 LLM 판단은 근거(인용·원문)를 함께 남긴다 — 채점이 블랙박스가 되지 않도록.

> **나의 판단**: 이 다섯 항목에서 키워드/regex를 더 정교화하는 것은 한계 수익이 빠르게
> 떨어진다(항목 4에서 입증). 규칙은 "후보를 빠짐없이 모으는" 역할에 한정하고, 변별의
> 책임은 LLM에 두는 것이 비용·정확도·재현성 면에서 가장 합리적이다.
