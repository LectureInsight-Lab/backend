## 2. 발화 완결성 - 이수민
- **세부 기준:** 강사가 문장을 끝까지 맺는가 (종결어미로 완결되는 발화 비율)
- **최종 결론**
    - 경로: `app/preprocessing/item02_completeness.py`
      (문장화 인프라는 공용 `sentencizer.py`, 항목 2 채점만 분리)
    - Input: STT 원문 → 문장화된 `Sentence` (Kiwi EF/EC 판정 포함)

    ```
    [Step 1] STT 라인을 타임스탬프 갭(>30초) 기준으로 발화 세그먼트 분리.
             (갭 임계 30초 = EDA 보정값. STT 타임스탬프는 발화 '시작점'이라 10초는 침묵 아님)
    [Step 2] 세그먼트 텍스트 merge — 원본 라인 인덱스·타임스탬프를 char offset으로 보존.
    [Step 3] Kiwi로 문장 분리 (split_into_sents).
    [Step 4] 각 문장 마지막 '실질' 형태소 EF/EC 판정 (Kiwi).
             - EF(종결어미) = 완결 / EC(연결어미) 등 = 불완결 / 기호는 건너뜀.
    [Step 5] completeness_rate = 완결 문장 수 / 판정 문장 수 × 100.
    [Step 6] completeness_score 밴드로 1~5 채점.
    ```
- **채점 기준표** (Kiwi 분포 재보정, 잠정)

    | 점수 | 기준 (completeness_rate) |
    | --- | --- |
    | 5 | ≥ 93% |
    | 4 | 87 ~ 93% |
    | 3 | 78 ~ 87% |
    | 2 | 68 ~ 78% |
    | 1 | < 68% |

## 3. 언어 일관성 (말투) - 이수민
- **세부 기준:** 존댓말/반말을 일관되게 사용하는가
- **최종 결론**
    - 경로: `app/preprocessing/item03_consistency.py`
    - Input: 문장화된 `Sentence` (`ending_morph`, `ending_tag`) — 항목 2와 문장화 공유

    ```
    [Step 1] 각 문장 마지막 EF 형태소 표면형으로 말투 분류 (Kiwi):
             격식존댓말(~니다/니까/시오) · 비격식존댓말(~요/죠) · 반말(그 외) · 중립(한다체 '~다', 非EF)
    [Step 2] 존댓말 = 격식 + 비격식. 중립(한다체)은 분모에서 제외.
    [Step 3] consistency_ratio = max(존댓말%, 반말%)   # 분모 = 존댓말 + 반말 → 정의상 50~100%
    [Step 4] violation_count = (존+반) − 지배 말투 문장 수.
    [Step 5] consistency_score 밴드로 1~5 채점. (혼용=감점, 현행 유지로 확정)
    ```
- **채점 기준표** (잠정 / 측정 검증됨)

    | 점수 | 기준 (consistency_ratio, 50~100) |
    | --- | --- |
    | 5 | ≥ 90% |
    | 4 | 80 ~ 90% |
    | 3 | 70 ~ 80% |
    | 2 | 60 ~ 70% |
    | 1 | < 60% (≈50% = 완전 혼용, 최악) |

    > 검증: 일관율 54%(현 강사)는 진짜 코드스위칭으로 확인(반말 표본 ~90% 실제). 측정은 신뢰,
    > '혼용=감점' 해석은 현행 유지 확정. 상세 scoring-bands.md 3절.

## 12. 발화 속도 적절성 - 이수민
- **세부 기준:** 말 속도가 적절한가 (너무 빠르거나 느리지 않은가)
- **최종 결론**
    - 경로: `app/preprocessing/item12_pace.py`
    - Input: STT 원문 → `Utterance` 리스트

    ```
    [Step 1] 음절(한글 글자) 수 카운트. (어절 WPM은 보조/진단용)
    [Step 2] 말하는 시간 근사 = 인접 발화 갭 ≤20초 구간만 합산 (긴 침묵 제외).
    [Step 3] spm_speaking = 음절 / 말하는 시간(분).   # 헤드라인, 아나운서 SPM과 동일 축
    [Step 4] (옵션) slowdown_ratio = 핵심 구간 SPM / 전체 평균 (<0.85 = 핵심 구간 감속).
             ※ 핵심 구간 앵커는 타 항목 산출물 — 미연결 시 None.
    [Step 5] score_band 으로 1~5 채점 (아나운서 355 음절/분 기준).
    ```
- **채점 기준표** (spm_speaking 기준, 아나운서 355 앵커)

    | 점수 | 기준 |
    | --- | --- |
    | 5 | 215~300 + 핵심 구간 감속(slowdown<0.85) |
    | 4 | 215~300(균일) · 195~215 · 300~340 |
    | 3 | 160~195 · 340~390 |
    | 2 | 125~160 · 390~445 |
    | 1 | <125 · >445 |

## 16. 이해 확인 질문 - 이수민
- **세부 기준:** 강의 중 수강생의 이해 여부를 확인하는 질문을 적절한 빈도·타이밍으로 하는가
- **최종 결론**
    - 경로: `app/preprocessing/item16_comprehension_check.py`
    - Input: STT 원문 → `Utterance` 리스트

    ```
    [Step 1] 이해 확인 의문형 패턴(regex) 탐지 — 라인 단위 1회.
             (실데이터 마커: "되셨어요/알겠어요/맞죠/괜찮으세요/보이시죠..." 고정밀 패턴)
    [Step 2] check_count, check_rate = check_count / 강의 시간(분).
    [Step 3] (옵션) timing_ratio = 앵커(개념/예시/실습) 직후 5분 이내 확인 비율.
             ※ 정식 앵커는 타 항목 산출물 — 미연결 시 None / EDA는 cue 프록시.
    [Step 4] '진짜 대기' 판정 = 확인이 라인 끝 + 강사 본인 갭 분포 상위(p90) → 습관 추임새와 구분.
    [Step 5] check_rate_score + timing_bonus 로 1~5 채점.
    ```
- **채점 기준표**

    | 점수 | 기준 (check_rate, 분당 확인 빈도) |
    | --- | --- |
    | 5 | ≥ 0.10 (Rosenshine: 10~15분당 1회) |
    | 4 | ≥ 0.07 |
    | 3 | ≥ 0.05 |
    | 2 | ≥ 0.03 |
    | 1 | < 0.03 |
    | 보정 | timing_ratio ≥70% → +1 / <30% → −1 (최종 1~5 clip) |

## 17. 참여 유도 - 이수민
- **세부 기준:** 수강생이 직접 시도(실습)하도록 유도하고, 시도 시간·결과 확인을 주는가
- **최종 결론**
    - 경로: `app/preprocessing/item17_engagement.py`
    - Input: STT 원문 → `Utterance` 리스트

    ```
    [Step 1] 학생 명령형 유도 발화(regex) 탐지 — "~해보세요/봐요" 등.
             (강사 본인 시범 '해볼게요/해봅시다'는 어미로 자동 제외)
    [Step 2] engagement_count + 유도 직후 갭(gap_after) + 5분 내 결과확인 피드백(tic 제외) 부착.
    [Step 3] avg_gap = 유도 후 평균 침묵 갭. 진짜 시도 넘김 = 유도 후 ≥30초 침묵.
    [Step 4] engagement_score + gap_bonus + feedback_bonus 로 1~5 채점.
    ```
- **채점 기준표** (합산 후 1~5 clip)

    | 항목 | 점수 |
    | --- | --- |
    | engagement_score | 유도 ≥2회 → 3 / 1회 → 2 / 0회 → 1 (Flanders: 최소 2회) |
    | gap_bonus | avg_gap ≥ 15초 → +1 |
    | feedback_bonus | 결과 확인 피드백 있음 → +1 |
