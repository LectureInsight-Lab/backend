## 0. 배경 — 왜 골든셋인가
채점 로직(regex·임계값·밴드)이 전부 손으로 만든 것이라, "잘 잡겠지"를 **수치로 증명**해야 한다.
- 정확도 측정(recall/precision) → 클라이언트·팀에 신뢰 근거
- 임계값·패턴 튜닝의 **객관적 기준**(목적함수)
- 회귀 방지, 오류 진단, 방법 비교
- 02·03 잠정 밴드 "팀 협의"를 의견이 아니라 **증거로 종결**

> 항목 2·3은 검증 경로 존재(3 = honorific `gold_testset.json`, 2 = Kiwi 태깅 감사).
> **미구축 = 12·13·16·17.** 본 문서는 16·17.

## 1. 방법론 (확정)
- **2단계**: ① 1차 후보군 추출(recall) → ② 2차 채점(scoring)
- **baseline(비교군) 대비 향상 측정**: baseline = 루브릭 spec 예시 regex / 비교군 = 우리 데이터튜닝 regex
- **생성 방식**: STT → Kiwi 문장 인덱싱 → 넓은 net으로 후보 surfacing → **EVAL_MODEL이 라벨** → gold
- **gold 라벨러 = `EVAL_MODEL` (= `models/gemini-2.5-pro`)** — config/.env에 명시(production `LLM_MODEL`=flash와 분리).
  강한 모델로 정답을 만들고 cheaper flash production을 채점하는 구조(서로 달라 순환 없음).
  ※ 본 노트의 초기 수치는 Claude 1차 라벨 기준 — `scripts/build_goldset.py`로 Gemini Pro 재라벨 + Claude와 IAA 비교 예정.
- **단위**: Kiwi 문장 (gold·detector 동일 단위로 공정 비교)
- **대상**: 5개 파일 (2026-02-09 ~ 02-13), **항목별 일자별 개별 JSON** (16×5 + 17×5 = 10개)
- **kss→Kiwi**: 형태소 분석을 이미 Kiwi로 전환했으므로 문장 분리도 `kiwi.split_into_sents`로 통일

## 2. 핵심 원칙 (모든 결정의 기준)
> **모호한 범주에 binary를 강제하지 말고, 등급 라벨로 담는다.**
- 이유: ① 정보 손실 방지 ② 임계 결정을 나중으로 미뤄도 **재라벨 불필요**
- 16의 "됐어요", 17의 "해보자" 둘 다 본질적 회색지대 → 이 원칙으로 수렴
- **1차(텍스트 = 의도) ≠ 2차(갭 = 행동)** 를 분리한다

## 3. 항목 16 — 이해 확인 질문  ✅ 1차 완료(5파일)

### 발견
1. **루브릭 spec 예시가 실강의에 0건** — "이해하셨나요/질문 있으신가요/따라오시나요" → baseline recall **0%**.
2. **"됐어요"의 이중성** — 상태서술 vs 이해확인. 실측(5강의): 시-높임(되셨/하셨) **222** vs bare 됐 **212**(그중 **41%가 "X가/이 됐" 서술**).
3. **production recall 갭** — "이해 가죠/가시죠"(이해 가다 구어형), "됐습니까/됐냐"(어미 누락), "되셨지/알겠지"(bare 지) 미탐.
4. **production precision 누수** — `됐` 가지가 bare 됐어요(서술)까지 이해확인으로 오집계.

### 해결방향 · 결정
- **판별 규칙(확정)**: `시-높임(되셨/되시/하셨/오셨/보이시/괜찮으시)` **또는** `의문형(됐을까요/됐습니까/됐냐)` = CHECK. **bare 평서 됐어요/왔어요(시·의문 없음) = 제외.**
- **라벨**: `is_check ∈ {Y, N}` (binary로 충분)
- **detector 개선 리스트**: ① 이해 가다 구어형(가죠/가시죠/하죠) 추가 ② 어미 확장(습니까/냐/지) ③ `됐` 가지에 시-높임 or 의문 조건 추가(precision)

### 결과 (5파일: 02-09 ~ 02-13)
| 파일 | gold | baseline(spec) | production |
|---|---|---|---|
| 02-09 | 56 | 0% | 68% |
| 02-10 | 51 | 0% | 61% |
| 02-11 | 48 | 0% | 73% |
| 02-12 | 27 | 0% | 67% |
| 02-13 | 43 | 0% | 67% |
| **종합** | **225** | **0%** | **67% (+67%p)** |

- 5파일 전반 61~73%로 일관 → 놓침 33%가 동일 유형(이해 가죠/됐습니까/됐냐)이라 패턴 보강 효과 예측 가능
- 산출: `data/gold/item16_02-09.json` ~ `item16_02-13.json`
- ※ LLM(1차) 라벨 — 본인 스팟 검수 후 확정

## 4. 항목 17 — 참여 유도  ✅ 1차 완료(5파일, 3-tier)

### 발견
1. **production recall 심각** — strict gold(학생 명령형)에서도 **3/18 = 17%**(02-09). 원인:
   - `_ACTION` 목록 누락(넣어/생각해/바꿔/리턴해)
   - '요' 강제 → bare "써봐/넣어봐/해봐" 미탐
   - STT 잘림("해보세"=요 빠짐) 미탐
2. **청유형 "해보자" 정의 문제** — 강사가 명령형(18)보다 **청유형(53, 2.9배)** 을 압도적으로 사용. production은 청유형을 설계상 **제외**(세요/봐요만).
3. **청유형의 학생-vs-강사 자동 분리 불가** — 텍스트 단서로 **75%(40/53)가 모호**.
   - 양성 단서(여러분/직접/번)는 희박·노이즈 / 음성 단서(제가/하겠습니다/볼게요)는 신뢰됨
   - 갭(행동) 신호도 약함(모호군 직후갭 중앙 **0s** — 강사가 시켜놓고 안 기다림)

### 해결방향 · 결정
- **3-tier 라벨(확정)**:
  - `strong` = 학생 명령형 (세요/봐요/봐/어라/주세요)
  - `weak` = 청유 과제제시 (풀어보자/구현해보자) **− 강사 본인 시범**
  - `no` = 강사 시범(제가/하겠습니다/볼게요/보여/연습) · 기술용어 오탐(직접 호출) · 무관
- **음성 필터(신뢰 가능)**: 위 강사 본인 단서가 있으면 제외
- **"학생 대상만 자동 추출"은 불가** → 등급 라벨 + 음성 제거로 대응
- **1차(의도) / 2차(갭) 분리**: 진짜 참여 여부는 텍스트가 아니라 갭(`genuine_handoff`, 갭≥30s)이 판정
- **detector 개선**: `_ACTION` 확장, bare 어미(봐/써/넣어봐) 허용, STT 잘림 대응

### 결과 (5파일, 3-tier)
| 파일 | strong | weak | prod@strong | prod@strong+weak |
|---|---|---|---|---|
| 02-09 | 14 | 31 | 21% | 7% |
| 02-10 | 7 | 35 | 57% | 10% |
| 02-11 | 12 | 35 | 50% | 13% |
| 02-12 | 7 | 12 | 86% | 32% |
| 02-13 | 6 | 14 | 100% | 30% |
| **종합** | **46** | **127** | **54%** | **14%** |

- baseline(spec)@strong = 28%
- **recall@strong 54%**: 학생 명령형 절반 놓침(STT 잘림·_ACTION 누락, 파일별 21~100% 편차)
- **recall@strong+weak 14%**: 강사 주력인 청유형(weak 127)을 production이 거의 못 잡음 → "정의가 현실과 어긋난" recall 문제
- 산출: `data/gold/item17_02-09.json` ~ `item17_02-13.json` · ※ LLM(1차) 라벨, 검수 필요
- **recall 두 기준**: `recall@strong`(detector가 자기 정의조차 얼마나 잡나) / `recall@strong+weak`(현실 참여유도)
- **precision 병행** — 16의 "됐어요 헛집계" 같은 누수 측정
- **baseline = 루브릭 spec regex** (16에서 0% 입증)
- 두 기준을 같이 보면 **임계 결정(strong-only vs +weak)을 재라벨 없이** 나중에 가능

## 7. 부수 발견 / 메모
- **STT 긴 merge 문장**: 유도/확인 표현이 문장 중간에 묻힘 → 현재 문장 단위 "표현 포함 시 positive". 라인 단위 옵션 보류.
- **골든셋의 가치 실증**: recall뿐 아니라 precision 누수(16)·패턴 개선점(16·17)까지 데이터로 짚어줌.
