---

## 설계 원칙

1. **조작적 정의 우선**: 모든 항목은 전사본에서 계산 가능한 절차로 정의
2. **수치 근거 명시**: 임계값은 논문·연구에서 도출하거나 명시적 논리로 산출
3. **상호 배타적 구간**: 점수 구간이 겹치지 않으며 경계값은 높은 점수에 귀속
4. **LLM 의존 최소화**: 규칙/통계로 측정 가능한 항목은 LLM 사용 안 함

## 공통 정의

| 용어 | 정의 |
|---|---|
| **어절** | 띄어쓰기 단위 (`text.split()`) |

## 카테고리 1. 언어 표현 품질

---

### 1-1. 불필요한 반복 표현 ★높음

#### 조작적 정의
강의 전체 및 5분 슬라이딩 윈도우에서, 내용 전달에 기여하지 않는 간투사·담화 표지가 전체 어절에서 차지하는 비율(FWR)과 분당 발생 빈도.

#### 불필요 단어 사전
```
[간투사]      음, 어, 아, 에, 저(간투사 용법)
[담화 표지]   이제, 근데, 그니까, 뭐(간투사), 어떻게 보면, 이런 식으로
[접속 남용]   그래서(3회/5분 초과), 그리고(3회/5분 초과)
```
> 사전 출처: 전영옥 (2002), "한국어 담화 표지 연구", *화법연구* 4호 — 한국어 구어 담화 표지 빈도 목록 제공

#### 측정 절차
```
1. KoNLPy Mecab으로 전체 어절 수 계산
2. 불필요 단어 사전 매칭으로 filler_count 계산
3. FWR(%) = filler_count / total_words × 100
4. 분당 발생 수 = filler_count / 강의 시간(분)
5. 슬라이딩 윈도우: 크기=5분, 스텝=2.5분(50% 오버랩) → 창별 FWR 계산
6. window_max_fwr = 창별 FWR 최댓값
```

#### 채점 기준

| 점수 | 전체 FWR | 분당 발생 수 | window_max_fwr |
|:---:|---|---|---|
| **5** | ≤ 3% | ≤ 5회/분 | ≤ 8% |
| **4** | 3–6% | 5–10회/분 | ≤ 10% |
| **3** | 6–10% | 10–17회/분 | ≤ 15% |
| **2** | 10–15% | 17–26회/분 | > 15% |
| **1** | > 15% | > 26회/분 | — |

> **임계값 근거**: Laske et al. (2024), *Journal of Applied Behavior Analysis* — "≤5 disfluencies/min은 발표 효과에 부정적 영향 없음; 12회/분부터 명확한 저하." 평균 강의 속도 175 어절/분 기준: 5회/175 ≈ 2.9% → 5점 기준 3%로 반올림.  
> — [논문 링크](https://onlinelibrary.wiley.com/doi/abs/10.1002/jaba.1093)

### 1-2. 발화 완결성 ●중간

#### 조작적 정의
강사 발화 중 종결어미(EF)로 끝나는 완결 문장의 비율. 연결어미(EC)나 호흡 단절로 끊긴 문장은 불완결로 분류.

#### 완결·불완결 판정 기준

| 분류 | 형태소 태그 | 예시 |
|---|---|---|
| **완결** | EF(종결어미) | -습니다, -어요, -거든요, -네요, -죠, -ㄹ게요 |
| **불완결** | EC(연결어미)로 문장 종료 | "그래서 이게 중요하고..." |
| **불완결** | 발화 중단 (STT에서 "…" 또는 다음 타임스탬프 갭 > 10초 후 새 주제) | "이걸 보면 사실..." (이후 다른 내용) |

#### 측정 절차
```
1. 타임스탬프 갭 > 10초인 지점을 발화 세그먼트 경계로 분리
2. kss로 세그먼트 내 문장 분리
3. 각 문장의 마지막 형태소를 Mecab으로 추출 → EF/EC 판정
4. completeness_rate = 완결 문장 수 / 전체 문장 수 × 100
```

#### 채점 기준

| 점수 | completeness_rate | 불완결 비율 |
|:---:|---|---|
| **5** | ≥ 95% | < 5% |
| **4** | 90–95% | 5–10% |
| **3** | 82–90% | 10–18% |
| **2** | 72–82% | 18–28% |
| **1** | < 72% | > 28% |

> **임계값 근거**: rubric_draft.md 정의("끊긴 문장 < 5%이면 5점, > 15%이면 1점")를 5개 구간으로 선형 확장. 자연 발화에서 5–10%의 불완전 문장은 생리적 한계 내 허용 범위.

### 1-3. 언어 일관성 ●중간

#### 조작적 정의
강의 전체에서 존댓말 또는 반말 중 지배적 말투의 비율 (consistency_ratio). 지배적 말투가 아닌 발화가 혼용 횟수.

#### 종결 형태소 분류표

| 분류 | 해당 어미 | 예시 |
|---|---|---|
| **격식 존댓말** | -습니다, -입니다, -습니까 | "이렇게 합니다" |
| **비격식 존댓말** | -아요/어요, -죠, -세요, -거든요, -네요 | "이렇게 해요" |
| **반말** | -야, -아/어(반말), -지(반말), -다(구어), -거야 | "이렇게 해" |
| **중립** | 명사형 종결, 나열체 | 분모에서 제외 |

#### 측정 절차
```
1. kss로 문장 분리
2. Mecab으로 각 문장의 마지막 EF 형태소 추출
3. 위 분류표에 따라 [존댓말/반말/중립] 라벨링
4. formal_ratio = 존댓말 문장 수 / (전체 - 중립) × 100
5. informal_ratio = 반말 문장 수 / (전체 - 중립) × 100
6. consistency_ratio = max(formal_ratio, informal_ratio)
7. violation_count = (전체 - 중립) - (지배적 말투 문장 수)
```

> **보조 모델**: `j5ng/kcbert-formal-classifier` (HuggingFace) — KcBERT 기반 존댓말 분류기  
> [huggingface.co/j5ng/kcbert-formal-classifier](https://huggingface.co/j5ng/kcbert-formal-classifier)

#### 채점 기준

| 점수 | consistency_ratio | violation_count |
|:---:|---|---|
| **5** | ≥ 97% | 0–2회 |
| **4** | 93–97% | 3–5회 |
| **3** | 85–93% | 6–10회 |
| **2** | 75–85% | 11–18회 |
| **1** | < 75% | ≥ 19회 |

> **임계값 근거**: rubric_draft.md("3회 이하 혼용이면 3점") 기준점에서 5단계 구간 도출. 97%는 60분 강의(약 600문장 가정)에서 약 18회 이탈까지 허용하는 실용적 상한.

## 카테고리 2. 강의 도입 및 구조

### 2-1. 학습 목표 안내 ★높음

#### 조작적 정의
도입부 구간에서 오늘의 학습 목표와 강의 진행 순서를 명시적으로 제시하는가. **목표 제시 여부 × 순서 제시 여부 × 등장 시점** 세 축으로 평가.

#### 측정 절차
```
[Step 1] 도입부 구간 = min(전체 앞 15%, 첫 10분) 추출
[Step 2] 키워드 탐지 (regex)
  목표 키워드: "오늘 배울", "학습 목표", "오늘의 주제", "오늘은 ~ 다루겠", "오늘 다룰 내용"
  순서 키워드: "먼저 ~, 그다음", "순서는", "1번/2번", "첫 번째/두 번째"
[Step 3] 최초 등장 시점(분) 기록
[Step 4] LLM(haiku): 목표·순서가 실질적으로 명시되는지, 단순 주제 나열과 구분
```

#### 채점 기준

| 점수 | 목표 제시 | 순서 제시 | 등장 시점 |
|:---:|---|---|---|
| **5** | 명시적 (키워드 포함, 구체적) | 명시적 | ≤ 5분 |
| **4** | 명시적 | 명시적 | 5–10분 |
| **3** | 명시적 | 불명확 (언급만) | 10분 이내 |
| **2** | 주제만 언급 ("오늘은 JPA 합니다") | 없음 | — |
| **1** | 없음 | 없음 | — |

> **근거**: Rosenshine (2012), *American Educator* — Principle 1: "Begin each lesson with a short review of previous learning" 및 Principle 3: "Present new material in small steps." 명시적 학습 목표 제시는 효과적 수업의 필수 요소.  
> [Rosenshine 원문](https://www.aft.org/sites/default/files/Rosenshine.pdf)

### 2-2. 전날 복습 연계 ★높음

#### 조작적 정의
도입부 구간(min(첫 20분, 앞 25%))에서 이전 강의 내용을 실질적으로 복습하고, 오늘 강의 주제와 논리적으로 연결하는가.

#### 측정 절차
```
[Step 1] 복습 키워드 탐지 (도입부 구간)
  "저번에", "지난 시간에", "지난번에", "복습", "이전에", "앞서", "기억하시나요"
  → 키워드 없으면 → 1점 자동 배정 (이후 단계 불필요)
[Step 2] 복습 발화 길이 계산 (어절 수)
  복습 관련 연속 발화 블록의 총 어절 수
[Step 3] LLM(haiku): 오늘 강의와의 논리적 연결 여부 판단
  판단 기준: 복습 내용이 오늘 첫 개념과 인과적·확장적으로 연결되는가?
```

#### 채점 기준

| 점수 | 복습 발화 길이 | 오늘 내용과의 연결 (LLM) |
|:---:|---|---|
| **5** | ≥ 30 어절 | 논리적 연결 명확 ("저번에 X 배웠는데, 오늘은 그 위에 Y를 쌓습니다") |
| **4** | 15–30 어절 | 연결 있으나 다소 느슨 |
| **3** | 5–15 어절 | 단순 언급 ("저번에 X 했죠") |
| **2** | 1–5 어절 (키워드만) | 연결 없음 |
| **1** | 복습 키워드 없음 | — |

> **근거**: Rosenshine (2012) Principle 1: "Begin each lesson with a short review." 30 어절(약 3–4문장) 기준은 실질적 내용 전달이 가능한 최소 발화 단위.

### 2-3. 설명 순서 ●중간

#### 조작적 정의
본문 구간에서 **개념/정의 → 예시/비유 → 실습/적용** 순서로 설명이 구조적으로 진행되며, 역순 또는 단계 생략의 횟수.

#### 단계 분류 기준

| 레이블 | 발화 특징 |
|---|---|
| **[개념]** | 정의 패턴 ("X란", "X는 ~ 입니다"), 이론 설명, 원리 설명 |
| **[예시]** | "예를 들면", "~처럼", "가령", 비유 표현 |
| **[실습]** | "코드를 작성", "IDE를 열어", "직접 해보", "따라 해보세요" |
| **[전환]** | 요약, 마무리, 새 주제 이동 |

#### 측정 절차
```
[Step 1] 본문 구간을 3분 단위 청크로 분할
[Step 2] LLM(sonnet): 각 청크를 위 4개 레이블 중 하나로 분류
[Step 3] 레이블 시퀀스 분석
  순서 위반 케이스:
    ① [실습] → [개념] (역순)
    ② [개념] → [실습] ([예시] 단계 건너뜀)
    ③ 동일 레이블 연속 20분 이상 (단조로움)
[Step 4] violation_count = 위반 케이스 총합
```

#### 채점 기준

| 점수 | violation_count | 비고 |
|:---:|---|---|
| **5** | 0 | 전 구간 순서 완전 유지 |
| **4** | 1 | 경미한 이탈 1회 |
| **3** | 2–3 | 간헐적 이탈 |
| **2** | 4–5 | 빈번한 이탈 |
| **1** | ≥ 6 또는 특정 단계 완전 결여 | 구조 없음 |

> **근거**: Gagné (1965)의 수업 9단계(Conditions of Learning) — 자극 제시(개념) → 학습 안내(예시) → 수행 유도(실습) 순서. Sweller (1988)의 인지 부하 이론에서 이 순서가 외재적 인지 부하를 최소화함을 지지.

### 2-4. 핵심 내용 강조 ●중간

#### 조작적 정의
강의 내 명시적 강조 표현 빈도, 그리고 학습 목표(2-1 결과) 핵심 키워드가 다른 맥락에서 심화 설명을 동반하여 재등장하는 비율.

#### 측정 절차
```
[Step 1] 명시적 강조 표현 탐지 (regex)
  "중요한 건", "핵심은", "반드시", "꼭 기억", "다시 말해",
  "이게 핵심", "절대 잊으면 안 되는", "강조해서 말씀드리면"
  → emphasis_count 계산

[Step 2] 학습 목표 키워드 재등장 분석
  - 2-1에서 추출한 목표 키워드 목록 사용
  - 최초 등장 이후 재등장 시, 직후 2문장 내에 새로운 설명이 추가되는지 LLM(haiku) 판단
  - reinforcement_ratio = 심화 재등장 키워드 수 / 전체 목표 키워드 수 × 100
```

#### 채점 기준

| 점수 | emphasis_count | reinforcement_ratio |
|:---:|---|---|
| **5** | ≥ 3회 | ≥ 70% |
| **4** | 2회 | 50–70% |
| **3** | 1회 | 30–50% |
| **2** | 0회 | 단순 반복만 존재 |
| **1** | 0회 | 재등장 없음 |

> **근거**: Hattie & Timperley (2007), "The Power of Feedback", *Review of Educational Research* — 학습 목표와 연결된 반복 강조는 학습 효과를 높이는 핵심 요인. Rosenshine (2012) Principle 6: "Check for student understanding."

### 2-5. 마무리 요약 ▽낮음

#### 조작적 정의
마무리 구간에서 오늘 학습한 핵심 내용(학습 목표 키워드)을 명시적으로 재언급하며 요약하는가.

#### 측정 절차
```
[Step 1] 마무리 구간 추출
[Step 2] 요약 키워드 탐지 (regex)
  "오늘 배운", "정리하면", "요약하자면", "마무리로", "핵심은", "오늘 다룬"
[Step 3] 2-1 목표 키워드 중 마무리 구간에서 재언급된 수 카운트
[Step 4] LLM(haiku): 요약의 완결성 판단 (단순 나열 vs. 정리된 요약)
```

#### 채점 기준

| 점수 | 목표 키워드 재언급 수 | 요약 형식 |
|:---:|---|---|
| **5** | ≥ 3개 | 명시적 요약 + 다음 강의 예고 |
| **4** | 2개 | 명시적 요약 |
| **3** | 1개 | 있으나 형식적 |
| **2** | 0개 | "오늘 수업 마치겠습니다" 수준 |
| **1** | 0개 | 요약 없이 종료 |

## 카테고리 3. 개념 설명 명확성

---

### 3-1. 개념 정의 ★높음

#### 조작적 정의
핵심 기술 용어가 강의에서 최초 등장하는 시점으로부터 **3문장 이내**에 명시적 정의가 제공되는 비율 (definition_coverage).

#### 핵심 용어 목록 구성
```
[고정 사전] Java/백엔드 기술 용어:
  API, REST, HTTP, JPA, ORM, DTO, VO, Entity, Repository,
  Service, Controller, Spring, Bean, DI, IoC, MVC,
  interface, abstract, inheritance, polymorphism, ...

[동적 추출] TF-IDF 상위 20개 (강의 특화 용어)
  → 고정 사전 + 동적 추출의 합집합 사용
```

#### 정의 패턴 (regex)
```
"X란", "X는 .{1,50}(입니다|이에요|이란)", "X라고 하는",
"X를 정의하면", "X가 뭐냐면", "X라고 부르", "X를 뜻합니다"
```

#### 측정 절차
```
[Step 1] 용어 목록 구성 (고정 + TF-IDF)
[Step 2] 각 용어의 최초 등장 문장 인덱스 기록
[Step 3] 최초 등장 이후 3문장 이내에 정의 패턴 탐지
[Step 4] definition_coverage = 정의된 용어 수 / 전체 용어 수 × 100
```

#### 채점 기준

| 점수 | definition_coverage |
|:---:|---|
| **5** | ≥ 90% |
| **4** | 75–90% |
| **3** | 50–75% |
| **2** | 30–50% |
| **1** | < 30% |

> **근거**: Sweller (1988)의 인지 부하 이론 — 미정의 용어 사용은 외재적 인지 부하를 증가시켜 학습을 방해. 3문장 이내 기준은 자연 발화에서 용어 소개 후 즉시 설명하는 패턴(Tran et al., 2023)에서 도출.  
> — [arxiv 2306.14918](https://arxiv.org/abs/2306.14918)

---

### 3-2. 비유 및 예시 활용 ★높음

#### 조작적 정의
핵심 기술 용어가 최초 등장하는 시점으로부터 **5문장 이내**에 비유 또는 실생활 예시가 제공되는 비율 (analogy_coverage), 그리고 LLM이 판단한 비유의 개념 연결 적절성.

#### 측정 절차
```
[Step 1] 3-1 용어 목록 및 최초 등장 위치 재활용
[Step 2] 최초 등장 이후 5문장 이내 비유·예시 패턴 탐지 (regex)
  비유: "~처럼", "~와 같이", "~라고 생각하면", "~에 비유하면", "마치 ~"
  예시: "예를 들면", "예시로", "가령", "실제로 ~보면", "예컨대"
[Step 3] analogy_coverage = 비유·예시 동반 용어 수 / 전체 용어 수 × 100
[Step 4] LLM(sonnet, 4-shot): 표본 추출 5개에 대해 비유가 개념 핵심과
  연결되는지 평가 → appropriateness_ratio 계산
```

#### 채점 기준

| 점수 | analogy_coverage | appropriateness_ratio (LLM) |
|:---:|---|---|
| **5** | ≥ 70% | ≥ 80% |
| **4** | 50–70% | ≥ 70% |
| **3** | 30–50% | ≥ 50% |
| **2** | 10–30% | — |
| **1** | < 10% | — |

> **근거**: Mayer (2009)의 멀티미디어 학습 이론(Multimedia Learning) — 구체적 예시와 비유는 스키마 활성화를 통해 추상 개념 이해를 촉진. 5문장 이내 기준은 개념 등장과 비유 제공 사이의 최대 허용 인지 거리.

---

### 3-3. 선행 개념 확인 ●중간

#### 조작적 정의
강의 내 주제 전환점(topic shift)에서 이전 선행 개념을 확인하거나 연결하는 발화가 존재하는 비율 (prerequisite_coverage).

#### 주제 전환점 탐지 방법
```
[Step 1] 전사본을 2분 단위 청크로 분할
[Step 2] 인접 청크 간 KR-SBERT 코사인 유사도 계산
  sim[i] = cosine(embed[chunk_i], embed[chunk_i+1])
[Step 3] 전환점 탐지: sim[i] < (전체 sim 값의 하위 25% 백분위수)
  → 유사도가 급락하는 구간 = 주제 전환점
```

#### 선행 확인 표현 (regex)
```
"이거 기억나시죠", "앞서 봤던", "이전에 배운 .{1,20}(기반으로|이어서)",
"저번에 다뤘던", "먼저 .{1,10} 짚고", "~와 연결해서"
```

#### 측정 절차
```
[Step 4] 각 전환점 직전 청크에서 선행 확인 표현 탐지
[Step 5] prerequisite_coverage = 확인 있는 전환점 수 / 전체 전환점 수 × 100
```

#### 채점 기준

| 점수 | prerequisite_coverage |
|:---:|---|
| **5** | ≥ 85% |
| **4** | 70–85% |
| **3** | 50–70% |
| **2** | 30–50% |
| **1** | < 30% |

> **근거**: Ausubel (1968)의 유의미 학습 이론 — 새로운 지식은 기존 인지 구조(선행 개념)에 연결될 때 유의미하게 학습됨. 주제 전환점은 선행 개념 필요성이 가장 높은 시점.  
> Bueno et al. (2026) — [arxiv 2606.05180](https://arxiv.org/abs/2606.05180)

### 3-4. 발화 속도 적절성 ●중간

#### 조작적 정의
강의 전체 평균 분당 어절 수(WPM_kr)가 수강생이 내용을 처리하기에 적합한 범위 내에 있으며, 핵심 개념 설명 구간에서 속도 감소가 관찰되는가.

> **단위 선택 근거**: 음절 대비 어절(띄어쓰기 단위)이 한국어의 자연스러운 의미 단위이며, 영어 WPM 연구와 직접 비교 가능.

#### 측정 절차
```
[Step 1] WPM_kr = 전체 어절 수 / 강의 총 시간(분)
[Step 2] 5분 구간별 WPM_kr 계산 → 표준편차(SD_wpm) 계산
[Step 3] 핵심 구간 감속 여부 (3-1에서 개념 등장 직후 5분 구간)
  slowdown = (핵심 구간 WPM_kr) / (전체 평균 WPM_kr)
  slowdown < 0.85 → 감속 있음 (15% 이상 감속)
```

#### 채점 기준

| 점수 | WPM_kr (평균) | 핵심 구간 감속 |
|:---:|---|---|
| **5** | 150–200 어절/분 | slowdown < 0.85 (15%+ 감속) |
| **4** | 150–200 어절/분 | 감속 없음 (균일) |
| **3** | 200–240 또는 120–150 어절/분 | — |
| **2** | 240–290 또는 90–120 어절/분 | — |
| **1** | > 290 또는 < 90 어절/분 | — |

> **임계값 근거**: Kang & Kim (2023, arxiv 2312.00201), *Automated Lecture Style Assessment* — "150–250 WPM은 고품질 강의 속도 범위." 한국어 어절 ≈ 영어 단어 대비 정보 밀도 유사 → 동일 범위 적용. 200 어절/분 상한은 Tauroza & Allison (1990)에서 빠른 발화가 이해도를 저하시키는 임계점으로 확인.  
> — [arxiv 2312.00201](https://arxiv.org/pdf/2312.00201)

## 카테고리 4. 예시 및 실습 연계

### 4-1. 예시 적절성 ★높음

#### 조작적 정의
강의에서 사용된 예시가 수강생의 수준(Java 초~중급)에 적합하고, 실제 백엔드 업무 현장과 연관성이 있는가. **수준 적합성**과 **실무 연관성** 두 축을 독립 평가 후 종합.

#### 측정 절차
```
[Step 1] 예시 발화 추출 (regex: "예를 들면", "예시로", "가령", "실제로")
[Step 2] LLM(sonnet, 4-shot): 각 예시에 대해 독립 평가

  [수준 적합성] 판단 기준 (시스템 프롬프트에 주입):
  "수강생은 Java 문법은 알지만 Spring, JPA, REST API는 처음. 예시가 이 수준에 맞는가?"
  → [너무 쉬움 / 적절 / 너무 어려움]

  [실무 연관성] 판단 기준:
  "실제 백엔드 개발자(REST API, DB, 서버 배포)가 마주치는 상황인가?"
  → [무관 / 보통 / 직접 연관]

[Step 3] 각 카테고리별 비율 계산
  level_ok_ratio = "적절" 예시 수 / 전체 예시 수 × 100
  relevance_high_ratio = "직접 연관" 예시 수 / 전체 예시 수 × 100
```

#### 채점 기준

| 점수 | level_ok_ratio | relevance_high_ratio |
|:---:|---|---|
| **5** | ≥ 80% | ≥ 70% |
| **4** | ≥ 70% | ≥ 50% |
| **3** | ≥ 50% | ≥ 30% |
| **2** | < 50% | — |
| **1** | 예시 없음 | — |

> **근거**: Kang & Kim (2023, arxiv 2312.00201) — 강의 품질 지표로 예시의 수준 연관성과 현실성 포함. LLM-Rubric (Elaraby et al., 2025) 방식으로 루브릭 기준을 LLM에 직접 제공.  
> — [arxiv 2501.00274](https://arxiv.org/abs/2501.00274)

### 4-2. 실습 연계 ★높음

#### 조작적 정의
이론 설명 이후 실습 구간으로 전환될 때, 이론과 실습이 동일 주제를 다루고 명시적 연결 표현을 동반하는가. **주제 연속성(코사인 유사도)** 과 **연결 표현 유무** 두 축으로 평가.

#### 측정 절차
```
[Step 1] 실습 시작 발화 탐지 (regex)
  "코드를 작성", "IDE를 열어서", "직접 해보", "따라 해보세요",
  "이제 실습", "구현해보겠습니다"
  → 없으면 N/A 처리

[Step 2] 이론 구간 = 실습 시작 직전 5분 발화 추출

[Step 3] 주제 연속성 계산
  similarity = cosine(KR-SBERT(이론 구간), KR-SBERT(실습 초반 5분))

[Step 4] 연결 표현 탐지 (regex)
  "방금 배운 .{1,20}(직접|구현|작성)", "앞서 설명한 것처럼",
  "이걸 이제 코드로", "이론에서 본 것과 같이"
```

#### 채점 기준

| 점수 | similarity | 연결 표현 |
|:---:|---|---|
| **5** | ≥ 0.80 | 있음 |
| **4** | 0.65–0.80 | 있음 |
| **3** | 0.65–0.80 | 없음 |
| **2** | 0.50–0.65 | — |
| **1** | < 0.50 또는 실습 없음 | — |
| **N/A** | 실습 발화 탐지 안 됨 | — |

> **근거**: 코사인 유사도 0.65 임계값은 KR-SBERT 논문의 의미적 유사성(semantic similarity) 기준에서 "관련 있음"으로 분류되는 하한값. 0.80 이상은 "높은 연관성"으로 분류.

### 4-3. 오류 대응 ●중간

#### 조작적 정의
실습 중 오류가 발생했을 때, 강사가 원인을 설명하고(A) 단계적 해결을 안내하며(B) 해결 여부를 확인하는가(C). 오류 탐지 건수가 0이면 N/A.

#### 오류 발생 탐지 (regex)
```
"오류가", "에러가", "error", "Error", "exception", "Exception",
"안 되네요", "이상하게", "왜 이게", "문제가 생겼", "실패했"
```

#### 침묵 보조 탐지
```
타임스탬프 갭 > 8초 이후 오류 키워드 등장 → 강사가 오류를 인지하고 대응하는 패턴
```

#### 측정 절차
```
[Step 1] 오류 키워드 탐지 → error_count 계산
  → 0건이면 N/A 처리
[Step 2] 각 오류 발화 이후 10문장을 응답 블록으로 추출
[Step 3] LLM(sonnet): 응답 블록에 대해 세 가지 판단
  A: 오류의 원인을 설명했는가? (예/아니오)
  B: 해결 방법을 단계별로 안내했는가? (예/아니오)
  C: 해결 후 "됐죠?", "잘 되셨나요?" 등 확인했는가? (예/아니오)
[Step 4] 다수 오류 발생 시 A·B·C 각각의 충족률로 점수 결정
```

#### 채점 기준

| 점수 | A (원인) | B (해결) | C (확인) |
|:---:|:---:|:---:|:---:|
| **5** | ✓ (모든 오류) | ✓ | ✓ |
| **4** | ✓ | ✓ | ✗ |
| **3** | ✗ | ✓ | ✗ |
| **2** | ✗ | △ (결과만) | ✗ |
| **1** | ✗ | ✗ (무시) | ✗ |
| **N/A** | 오류 키워드 0건 | | |

## 카테고리 5. 수강생 상호작용

---

### 5-1. 이해 확인 질문 ★높음

#### 조작적 정의
강의 중 수강생의 이해 여부를 확인하는 질문의 분당 빈도(check_rate)와, 개념 설명 또는 실습 직후 적절한 타이밍에 이루어지는 비율(timing_ratio).

#### 이해 확인 발화 탐지 (regex)
```
"되셨어요", "이해하셨나요", "따라오시나요", "알겠어요",
"질문 있으신가요", "여기까지 괜찮으세요", "어렵지 않으셨나요",
"혹시 모르시는 분", "이해가 안 되시는 분"
```

#### 측정 절차
```
[Step 1] 이해 확인 발화 탐지 → check_count 계산
[Step 2] check_rate = check_count / 강의 총 시간(분)
[Step 3] 타이밍 적절성 계산
  타이밍 OK = 개념 정의 발화(3-1 기준) 이후 5분 이내
            OR 실습 구간 종료 이후 5분 이내
  timing_ratio = 타이밍 OK인 확인 수 / 전체 check_count × 100
```

#### 채점 기준

| 점수 | check_rate | timing_ratio |
|:---:|---|---|
| **5** | ≥ 0.10회/분 (1회/10분) | ≥ 70% |
| **4** | 0.07–0.10회/분 (1회/15분) | 50–70% |
| **3** | 0.05–0.07회/분 (1회/20분) | 30–50% |
| **2** | 0.03–0.05회/분 (1회/30분) | — |
| **1** | < 0.03회/분 또는 없음 | — |

> **임계값 근거**: Rosenshine (2012), *American Educator* — "More effective teachers checked for understanding every 10–15 minutes." 10분당 1회 = 0.10회/분을 5점 기준으로 설정.  
> 타이밍 기준: Miller (1956)의 작업 기억 7±2 단위 이론에서 새 개념 5분 이내 확인이 단기 기억 공고화에 효과적.  
> — [Rosenshine 원문](https://www.aft.org/sites/default/files/Rosenshine.pdf)

---

### 5-2. 참여 유도 ★높음

#### 조작적 정의
수강생이 직접 시도하도록 유도하는 발화 횟수, 유도 후 실제 시도 시간(침묵 갭), 그리고 시도 후 결과 확인 발화 유무.

#### 참여 유도 발화 탐지 (regex)
```
"해보세요", "직접 .{1,10}해보", "스스로 .{1,10}해보",
"먼저 혼자", "풀어보세요", "작성해보세요", "구현해보세요"
```

#### 침묵 갭 측정
```
gap_time(초) = 참여 유도 발화 종료 타임스탬프
             - 다음 강사 발화 시작 타임스탬프
```

#### 확인 피드백 탐지 (regex)
```
"어떻게 됐어요", "됐나요", "잘 되셨나요", "완성하셨나요",
"어떤 결과가 나왔나요", "에러 없으신가요"
```

#### 측정 절차
```
[Step 1] 참여 유도 발화 탐지 → engagement_count
[Step 2] 각 유도 발화 이후 gap_time 계산
  avg_gap = 모든 gap_time의 평균 (초)
[Step 3] 확인 피드백 유무 탐지 (gap 이후 5분 이내)
```

#### 채점 기준

| 점수 | engagement_count | avg_gap | 확인 피드백 |
|:---:|---|---|---|
| **5** | ≥ 2회 | ≥ 30초 | 있음 |
| **4** | ≥ 2회 | 15–30초 | 있음 |
| **3** | 1–2회 | < 15초 또는 측정 불가 | 있음 또는 없음 |
| **2** | 1회 | — | 없음 |
| **1** | 없음 | — | — |

> **임계값 근거**: 30초 갭 기준 = 실습 문제 최소 시도 시간 (타이핑 속도 50 WPM 기준, 20–30자 코드 작성에 약 25–35초 소요). Flanders (1960) 상호작용 분석: 교사 독점 발화 비율 > 70%는 저품질 수업의 지표 → 참여 유도 최소 2회를 3점 하한으로 설정.

---

### 5-3. 질문 응답 충분성 ★높음

#### 조작적 정의
수강생 질문(또는 강사가 언급한 질문)에 대해 충분한 길이(answer_length), 높은 정보 밀도(noun_density), 그리고 질문 핵심을 해소하는 내용으로 답변하는가.

#### 질문 탐지
```
[화자 분리 없을 경우]
  강사 발화 내 질문 언급 패턴:
  "질문이요", "~는 어떻게 되나요", "~하면 안 되나요", "~이 뭔가요"

[화자 분리 있을 경우]
  학생 발화 중 "?" 포함 발화
```

#### 측정 절차
```
[Step 1] 질문 발화 탐지
[Step 2] Q-A 페어 구성: 질문 이후 강사 발화 N문장 (다음 질문 발화 전까지)
[Step 3] answer_length = 응답 어절 수
[Step 4] noun_density = NNG(일반명사) + NNP(고유명사) 형태소 수
                       / 전체 형태소 수 × 100
         (KoNLPy Mecab 품사 태그 활용)
[Step 5] LLM(sonnet, 3-shot): 응답이 질문 핵심을 해소하는가?
  → [완전 해소(원인+해결) / 대부분 해소 / 부분 해소 / 표면적 답변 / 미해소]
```

#### 채점 기준

| 점수 | answer_length | noun_density | LLM 핵심 해소 |
|:---:|---|---|---|
| **5** | ≥ 30 어절 | ≥ 28% | 완전 해소 |
| **4** | 20–30 어절 | 22–28% | 대부분 해소 |
| **3** | 10–20 어절 | 18–22% | 부분 해소 |
| **2** | 5–10 어절 | < 18% | 표면적 답변 |
| **1** | < 5 어절 또는 무응답 | — | 미해소 또는 무시 |

> **임계값 근거**:  
> **answer_length**: 20 어절 = 일반적 설명 문장 2–3개 분량. 의미 있는 답변의 경험적 최솟값.  
> **noun_density ≥ 25%**: 한국어 구어 평균 명사 밀도 18–22% 대비, 정보 밀도가 높은 기술적 설명에서 25–30%가 관찰됨.  
> Bueno et al. (2026): 교수 품질 평가에서 답변 충분성은 다차원 지표 필요.  
> — [arxiv 2606.05180](https://arxiv.org/abs/2606.05180)
